# DBeaver SQL Column Lens 3.5.0

**SQL Column Lens** — расширение для SQL Editor в DBeaver, которое показывает рядом со значениями соответствующие им колонки.

Оно помогает читать и проверять длинные `INSERT`, `UPDATE`, `ON CONFLICT` и `MERGE`, не пересчитывая позиции значений вручную.

```sql
INSERT INTO dm.clients (id, name, inn, status)
VALUES (10, 'ООО Ромашка', '4253000000', 'active');
```

В компактном виде подсказки выглядят примерно так:

```text
id: 10, name: 'ООО Ромашка', inn: '4253000000', status: 'active'
```

В расширенном виде:

```text
id [int] #1: 10, name [varchar] #2: 'ООО Ромашка', ...
```

> Расширение не изменяет SQL, не выполняет запросы и не отправляет содержимое редактора во внешние сервисы. Анализ выполняется локально внутри DBeaver.

## Возможности версии 3.5.0

- кнопка **Column Lens** с выпадающим меню в панели SQL Editor;
- обычное нажатие включает или выключает расширение;
- стрелка открывает выбор режима и быстрые действия;
- иконка показывает текущее состояние;
- режимы **Умный**, **Активное значение**, **Текущий запрос** и **Весь редактор**;
- Умный режим используется по умолчанию;
- последний выбранный режим запоминается для новых вкладок;
- каждая открытая SQL-вкладка хранит собственное временное состояние;
- автоматическая защита от большого количества подсказок;
- временная команда **Показать все в этой вкладке**;
- компактный и расширенный вид подписей;
- сокращение длинных имён колонок;
- типы колонок из активного подключения DBeaver, когда метаданные доступны;
- парная подсветка значения и соответствующей колонки;
- подробная информация при наведении;
- отображение режима и количества подсказок в status line;
- команды **Обновить подсказки** и **Сбросить слой отображения**;
- фоновый анализ SQL без блокировки интерфейса редактора.

## Системные требования

- настольная версия DBeaver на базе Eclipse/SWT;
- Java 21;
- SQL Editor DBeaver;
- локальная копия репозитория с папкой `sql-column-lens-v3.5.0`.

Расширение собрано с требованием:

```text
Bundle-RequiredExecutionEnvironment: JavaSE-21
```

### Как проверить Java в DBeaver

1. Откройте `Help → About DBeaver`.
2. Нажмите `Installation Details`.
3. Перейдите на вкладку `Configuration`.
4. Найдите `java.version` или `java.runtime.version`.
5. Версия должна быть `21` или новее.

Расширение предназначено для desktop-версии DBeaver. В CloudBeaver оно не устанавливается.

## Установка в DBeaver

Установка выполняется через стандартный мастер DBeaver:

```text
Help → Install New Software…
```

Клонируйте репозиторий:

```bash
git clone <адрес-репозитория>
```

Либо скачайте репозиторий архивом через интерфейс Git-сервиса и полностью распакуйте его.

После этого на диске должна существовать папка:

```text
<путь-к-репозиторию>/sql-column-lens-v3.5.0
```

Проверьте, что внутри находятся:

```text
artifacts.jar
content.jar
features/
plugins/
```

### 2. Откройте мастер установки

1. Запустите DBeaver.
2. Откройте `Help → Install New Software…`.
3. Дождитесь появления окна **Available Software**.

### 3. Добавьте локальный репозиторий

1. Нажмите `Add…` справа от поля **Work with**.
2. В поле **Name** укажите:

   ```text
   SQL Column Lens 3.5.0
   ```

3. Нажмите `Local…`.
4. Выберите папку:

   ```text
   <путь-к-репозиторию>/sql-column-lens-v3.5.0
   ```

5. Подтвердите выбор папки.
6. Нажмите `Add`.

Корректный путь заканчивается на:

```text
.../dbeaver-sql-column-lens/sql-column-lens-v3.5.0
```

Не выбирайте:

```text
.../dbeaver-sql-column-lens
.../sql-column-lens-v3.5.0/features
.../sql-column-lens-v3.5.0/plugins
.../sql-column-lens-v3.5.0/content.jar
.../sql-column-lens-v3.5.0/artifacts.jar
```

### 4. Выберите расширение

После чтения metadata в списке появится:

```text
DBeaver SQL Column Lens
```

1. Установите флажок рядом с **DBeaver SQL Column Lens**.
2. Нажмите `Next`.
3. Проверьте название и версию компонента.
4. Нажмите `Next`.
5. Примите условия лицензии.
6. Нажмите `Finish`.

Когда список пустой, снимите флажок:

```text
Group items by category
```

Feature может отображаться без категории — это нормально.

### 5. Подтвердите установку

DBeaver может показать предупреждение о неподписанном содержимом. После проверки источника файлов подтвердите продолжение установки.

### 6. Перезапустите DBeaver

После завершения нажмите:

```text
Restart Now
```

Расширение активируется после полного перезапуска DBeaver.

## Быстрый старт

1. Откройте SQL-файл в SQL Editor.
2. Нажмите основную часть кнопки **Column Lens**, чтобы включить расширение.
3. Откройте меню стрелкой рядом с кнопкой.
4. Оставьте **Умный режим**.
5. Поставьте курсор внутрь нужного `INSERT`, `UPDATE` или `MERGE`.
6. Для просмотра части большого SQL выделите нужный фрагмент.
7. Для одной подписи выберите **Только значение под курсором**.
8. Для небольшого файла можно выбрать **Весь редактор**.

Для повседневной работы рекомендуется **Умный режим**.

## Кнопка Column Lens

Кнопка является split-button и состоит из основной области и стрелки.

### Основное нажатие

- включает расширение в активной SQL-вкладке;
- повторное нажатие выключает расширение;
- выбранный режим сохраняется;
- состояние других открытых вкладок не изменяется.

### Выпадающее меню

Меню содержит:

```text
Умный режим
Только значение под курсором
Текущий SQL-запрос
Весь редактор

Фон подписей
Парная подсветка
Вид подписей → Компактный / Расширенный

Показать все в этой вкладке
Обновить подсказки
Сбросить слой отображения
Настройки…
```

Маркер рядом с пунктом показывает активный режим или включённую настройку.

### Иконка состояния

Иконка меняется в зависимости от состояния:

- расширение выключено;
- Умный режим;
- Активное значение;
- Текущий запрос;
- Весь редактор.

---

## Режимы отображения

| Режим | Поведение | Нагрузка |
|---|---|---:|
| **Умный** | При выделении показывает mappings выделенного фрагмента, иначе текущего SQL-запроса | Низкая |
| **Активное значение** | Показывает одну подпись около значения под курсором | Минимальная |
| **Текущий запрос** | Показывает все значения текущего `INSERT`, `UPDATE`, `ON CONFLICT` или `MERGE` | Низкая |
| **Весь редактор** | Показывает mappings во всех поддерживаемых запросах документа | Повышенная |

### Умный режим

Это режим по умолчанию.

Без выделения расширение показывает mappings только того SQL statement, в котором находится курсор.

Например, если файл содержит 11 больших `INSERT`, а текущий запрос содержит 19 значений, будут показаны только эти 19 подсказок.

При выделении текста расширение оставляет mappings, относящиеся к выделенному фрагменту. Когда выделение не содержит распознанных значений, используется текущий запрос.

### Активное значение

Показывается только mapping значения под курсором.

Этот режим полезен:

- в длинных однострочных запросах;
- в очень больших SQL-файлах;
- для минимальной визуальной нагрузки;
- при большом количестве строк в `VALUES`.

### Текущий запрос

Показываются все mappings текущего SQL statement. При перемещении курсора в другой запрос набор подсказок обновляется.

### Весь редактор

Показываются mappings всех поддерживаемых запросов документа. Режим удобен для небольших файлов, но при большом числе mappings срабатывает безопасный лимит.

## Состояние отдельных вкладок

Каждая открытая SQL-вкладка хранит собственное временное состояние:

- включено или выключено расширение;
- выбранный режим;
- временное разрешение показать все mappings.

Пример:

- в небольшом SQL-файле можно выбрать **Весь редактор**;
- в большом загрузочном скрипте — **Текущий запрос**;
- переключение одной вкладки не изменяет уже открытые соседние вкладки.

После закрытия вкладки её временное состояние забывается.

Последний явно выбранный режим сохраняется как режим по умолчанию для новых SQL-вкладок.

---

## Защита от зависаний

Когда режим **Весь редактор** находит слишком много mappings, расширение автоматически снижает объём отображения.

Правило версии 3.5.0:

- до 300 mappings включительно можно показать весь редактор;
- начиная с 301 mapping используется текущий SQL-запрос;
- пользователь получает сообщение о безопасном переключении;
- команда **Показать все в этой вкладке** временно отключает ограничение только для активной вкладки.

Пример сообщения:

```text
Найдено 846 подсказок. Включён режим текущего запроса.
```

Команда **Показать все в этой вкладке** действует до закрытия вкладки или смены её временного состояния. Глобальный безопасный лимит при этом не изменяется.

## Внешний вид подписей

### Компактный

```text
id: 10
name: 'ООО Ромашка'
inn: '4253000000'
```

Подходит для большинства сценариев и создаёт меньшую нагрузку на layout.

### Расширенный

```text
id [int] #1: 10
name [varchar] #2: 'ООО Ромашка'
inn [varchar] #3: '4253000000'
```

Расширенный вид показывает:

- имя колонки;
- тип, когда он доступен;
- позицию значения в mapping;
- само значение.

### Сокращение длинных имён

Длинные имена отображаются с многоточием:

```text
status_closed_…: NULL
```

Полное имя можно посмотреть при наведении.

### Фон подписей

Пункт **Фон подписей** включает подложку под текстом inline-подсказки. Это улучшает читаемость на сложных темах редактора и поверх SQL-подсветки.

## Hover и парная подсветка

При наведении или работе с активным значением отображается дополнительная информация:

```text
Column: status_closed_name
Type: varchar(255)
Position: 16 of 19
Table: dm_esfl_esul.fct_esul
Value: NULL
```

Доступность типа и полного имени таблицы зависит от SQL и метаданных активного подключения.

При включённой **Парной подсветке** расширение одновременно выделяет:

- значение или выражение;
- соответствующее имя колонки в списке `INSERT`, tuple-назначении или другой поддерживаемой конструкции.

Это помогает визуально проверить связь между колонкой и значением.

## Status line

После включения, выключения или переключения режима в нижней строке состояния DBeaver кратковременно показывается информация:

```text
SQL Column Lens · Current statement · 19 hints
```

Она содержит:

- название расширения;
- активный режим;
- фактическое количество отображаемых подсказок.

Если сработала защита от большого количества mappings, status line показывает безопасный режим и соответствующее количество подсказок.

## Горячие клавиши

### Включить или выключить

По умолчанию:

```text
Alt+Shift+L
```

Команда переключает расширение в активной SQL-вкладке и не сбрасывает выбранный режим.

### Циклическое переключение режима

Отдельная команда переключает режимы последовательно:

```text
Активное значение → Текущий запрос → Весь редактор
```

Комбинацию можно назначить через стандартные настройки DBeaver:

```text
Window → Preferences → General → Keys
```

В поле поиска введите:

```text
Column Lens
```

Команды находятся в категории **SQL Column Lens**.

Когда `Alt+Shift+L` конфликтует с другой командой, назначьте удобную комбинацию в разделе Keys.

## Обновление и сброс отображения

### Обновить подсказки

Команда повторно анализирует актуальный текст редактора и перестраивает mappings.

Используйте её, когда:

- SQL был значительно изменён;
- сменилось подключение;
- метаданные таблицы стали доступны;
- подсказки не успели обновиться после внешнего изменения документа.

### Сбросить слой отображения

Команда полностью удаляет текущий painter-слой, очищает его геометрию и создаёт отображение заново.

Используйте её, когда:

- подпись визуально осталась на старом месте;
- редактор изменил layout после сворачивания блоков;
- масштабирование или тема оставили некорректную геометрию;
- стороннее расширение повлияло на отрисовку SQL Editor.

Перезапуск DBeaver обычно не требуется.

## Настройки

Открыть настройки можно через пункт **Настройки…** в меню Column Lens либо через Preferences DBeaver.

Основные параметры:

- режим по умолчанию для новых вкладок;
- компактный или расширенный вид;
- фон подписей;
- парная подсветка;
- отображение типов;
- максимальная длина имени колонки;
- безопасный лимит mappings;
- предупреждения о несовпадении количества колонок и значений.

Изменение глобальных настроек не обязано немедленно заменять временный режим уже открытой вкладки. Для применения изменений используйте **Обновить подсказки**.

## Поддерживаемые SQL-конструкции

SQL Column Lens использует tolerant-parser и сопоставляет колонки с выражениями верхнего уровня по позиции.

### `INSERT ... VALUES`

```sql
INSERT INTO app.users (
    id,
    name,
    payload,
    created_at
) VALUES (
    1,
    'Nikita',
    jsonb_build_object('active', true),
    current_timestamp
);
```

Поддерживаются:

- однострочные и многострочные запросы;
- функции и вложенные скобки;
- строки с запятыми;
- массивы;
- несколько строк `VALUES`.

```sql
INSERT INTO app.users (id, name, status)
VALUES
    (1, 'Ann', 1),
    (2, 'Bob', 0),
    (3, 'Kate', 1);
```

### `INSERT ... SELECT`

```sql
INSERT INTO app.user_archive (
    id,
    name,
    archived_at
)
SELECT
    u.id,
    upper(u.name),
    current_timestamp
FROM app.users u;
```

Для корректного результата рекомендуется использовать явный список выражений. `SELECT *` не разворачивается в физические колонки источника.

### `UPDATE ... SET`

```sql
UPDATE app.users
SET name = trim(' Nikita '),
    payload = jsonb_build_object('source', 'manual'),
    updated_at = current_timestamp
WHERE id = 1;
```

### Tuple-обновление

```sql
UPDATE app.users
SET (name, payload, updated_at) = (
    trim(' Nikita '),
    jsonb_build_object('source', 'manual'),
    current_timestamp
)
WHERE id = 1;
```

### `ON CONFLICT DO UPDATE`

```sql
INSERT INTO app.users (id, name, updated_at)
VALUES (1, 'Nikita', current_timestamp)
ON CONFLICT (id) DO UPDATE SET
    name = excluded.name,
    updated_at = current_timestamp;
```

### `MERGE`

```sql
MERGE INTO app.users target
USING app.users_stage source
ON target.id = source.id
WHEN MATCHED THEN UPDATE SET
    name = source.name,
    updated_at = current_timestamp
WHEN NOT MATCHED THEN INSERT (
    id,
    name,
    updated_at
) VALUES (
    source.id,
    source.name,
    current_timestamp
);
```

Поддерживаются основные ветки `UPDATE SET` и `INSERT (...) VALUES (...)`.

### Предупреждения

При включённых предупреждениях расширение сообщает о типичных проблемах:

- количество колонок не совпадает с количеством значений;
- колонка указана несколько раз;
- для значения не найдена соответствующая колонка.

## Рекомендации по использованию

### Обычная ежедневная работа

Используйте **Умный режим**. Он показывает текущий statement, а при выделении ограничивает подсказки выбранным фрагментом.

### Один большой `INSERT`

Используйте **Текущий запрос**. Все значения текущего запроса будут видны, а остальные запросы файла не будут участвовать в layout.

### Очень длинная строка

Используйте **Активное значение**, чтобы видеть только одну подпись около курсора.

### Небольшой файл из нескольких запросов

Используйте **Весь редактор**, пока количество mappings не превышает безопасный лимит.

### Большой файл из множества `INSERT`

Оставьте **Умный режим** или **Текущий запрос**. Команду **Показать все в этой вкладке** используйте только для разовой проверки.

### Многострочный `VALUES`

Для большого количества строк рекомендуется **Умный режим** или **Активное значение**, чтобы не отображать сотни повторяющихся подписей одновременно.

## Устранение неполадок

### В Available Software ничего не появилось

Проверьте:

1. Выбрана именно папка `sql-column-lens-v3.5.0`.
2. В корне выбранной папки лежат `artifacts.jar` и `content.jar`.
3. В ней существуют папки `features` и `plugins`.
4. Репозиторий был полностью скачан или распакован.
5. В окне установки снят флажок **Group items by category**.

Удалите некорректную запись из списка **Work with**, затем повторно выполните `Add… → Local…`.

### DBeaver сообщает, что repository не найден

Обычно выбран неправильный уровень каталога. Поле Location должно указывать на папку, внутри которой непосредственно находятся:

```text
artifacts.jar
content.jar
features/
plugins/
```

### Ошибка чтения `content.jar` или `artifacts.jar`

- повторно скачайте репозиторий;
- проверьте, что Git LFS, антивирус или корпоративный прокси не заменил JAR текстовой заглушкой;
- сравните размер файлов с версией в Git;
- не открывайте и не пересохраняйте эти файлы архиватором.

### Ошибка зависимостей

Проверьте:

- используется desktop DBeaver;
- DBeaver запускается на Java 21;
- версия DBeaver содержит требуемые Eclipse/DBeaver bundles;
- устанавливается полный p2-репозиторий версии 3.5.0.

### Установка прошла, но кнопки нет

1. Полностью перезапустите DBeaver.
2. Откройте именно SQL Editor.
3. Проверьте bundle в `Help → About DBeaver → Installation Details → Plug-ins`.
4. Найдите `com.nikbobrovsky.dbeaver.sqlcolumnlens`.
5. Создайте новую SQL-вкладку.

### Расширение установлено, но подсказок нет

Проверьте:

- Column Lens включён в активной вкладке;
- курсор находится внутри поддерживаемого SQL statement;
- в запросе есть явный список целевых колонок;
- выбранный режим не ограничивает отображение другим участком документа;
- значение под курсором действительно распознано;
- после изменения SQL выполнена команда **Обновить подсказки**.

### Подписи остались на старых позициях

Выполните:

```text
Column Lens → Сбросить слой отображения
```

### DBeaver начинает замедляться

1. Переключитесь на **Умный режим**.
2. Для максимальной экономии выберите **Активное значение**.
3. Не используйте постоянный показ всего редактора в больших файлах.
4. Отключите расширенный вид, если в нём нет необходимости.
5. Выполните **Сбросить слой отображения**, если старая геометрия осталась после крупных изменений документа.

### Не показываются типы колонок

Типы зависят от активного подключения, разрешения имени таблицы и доступности метаданных. Основное сопоставление колонок со значениями продолжает работать без типов.

### Горячая клавиша не срабатывает

Откройте:

```text
Window → Preferences → General → Keys
```

Найдите команды **SQL Column Lens**, устраните конфликт и назначьте подходящую комбинацию.

## Ограничения

- parser является tolerant-parser, а не полной реализацией грамматики каждой СУБД;
- динамически формируемый SQL внутри строк не анализируется как отдельный запрос;
- `SELECT *` не разворачивается в список физических колонок источника;
- сложные vendor-specific конструкции могут распознаваться частично;
- типы и полное имя таблицы зависят от активного подключения и метаданных;
- временное состояние вкладки удаляется после её закрытия;
- интерактивные действия непосредственно внутри hover и навигация между значениями не входят в версию 3.5.0;
- специальные стратегии отображения отдельных строк многострочного `VALUES` не входят в версию 3.5.0.
