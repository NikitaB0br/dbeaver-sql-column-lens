# DBeaver SQL Column Lens 3.5.0

**SQL Column Lens** — расширение для SQL Editor в DBeaver, которое показывает рядом со значениями соответствующие им целевые колонки.

Расширение помогает читать и проверять длинные `INSERT`, `UPDATE`, `ON CONFLICT` и `MERGE`, не пересчитывая позиции значений вручную.

```sql
INSERT INTO dm.clients (id, name, inn, status)
VALUES (10, 'ООО Ромашка', '4253000000', 'active');
```

В компактном виде значения отображаются примерно так:

```text
id: 10, name: 'ООО Ромашка', inn: '4253000000', status: 'active'
```

В расширенном виде:

```text
id [int] #1: 10, name [varchar] #2: 'ООО Ромашка', ...
```

> SQL Column Lens не изменяет текст SQL и не выполняет запросы. Сопоставление колонок и выражений производится локально в редакторе.

## Возможности версии 3.5.0

- split-button **Column Lens** в панели SQL Editor;
- обычное нажатие включает или выключает расширение в активной вкладке;
- стрелка открывает меню режимов и быстрых действий;
- динамическая иконка показывает текущее состояние;
- режимы **Умный**, **Активное значение**, **Текущий запрос** и **Весь редактор**;
- независимое временное состояние для каждой открытой SQL-вкладки;
- запоминание последнего явно выбранного режима для новых вкладок;
- автоматический безопасный режим при большом количестве подсказок;
- временная команда **Показать все в этой вкладке**;
- компактный и расширенный вид подписей;
- сокращение длинных имён колонок через многоточие;
- получение типов колонок из активного подключения DBeaver;
- парная подсветка значения и соответствующей колонки;
- подробный hover для активного значения;
- индикатор режима и количества подсказок в status line;
- команды **Обновить подсказки** и **Сбросить слой отображения**;
- фоновый анализ SQL и атомарное обновление inline-подсказок.

## Системные требования

### Обязательно

- настольная версия DBeaver на базе Eclipse/SWT;
- Java 21;
- SQL Editor DBeaver;
- права на запись в каталог установки DBeaver для способа `dropins`.

Bundle собран с требованием:

```text
Bundle-RequiredExecutionEnvironment: JavaSE-21
```

Большинство актуальных сборок DBeaver поставляется со встроенной Java, но это следует проверить, если расширение не активируется.

### Как проверить Java в DBeaver

1. Откройте `Help → About DBeaver`.
2. Нажмите `Installation Details`.
3. Откройте вкладку `Configuration`.
4. Найдите параметры `java.version` или `java.runtime.version`.
5. Версия должна начинаться с `21` или быть новее и совместима с Java 21.

### Важное замечание

Расширение предназначено для desktop-версии DBeaver. Оно не является расширением браузера и не устанавливается в DBeaver CloudBeaver.

## Поддерживаемые SQL-конструкции

SQL Column Lens использует лёгкий tolerant-parser. Он не пытается полностью заменить SQL-парсер конкретной СУБД, а сопоставляет целевые колонки и выражения по их позиции.

### `INSERT ... VALUES`

```sql
INSERT INTO app.users (
    id,
    name,
    payload,
    created_at
) VALUES (
    1,
    'Nikita',
    jsonb_build_object('active', true),
    current_timestamp
);
```

Поддерживаются:

- однострочные и многострочные запросы;
- вложенные функции;
- строки с запятыми;
- массивы и выражения в скобках;
- несколько строк в `VALUES`.

```sql
INSERT INTO app.users (id, name, status)
VALUES
    (1, 'Ann', 1),
    (2, 'Bob', 0),
    (3, 'Kate', 1);
```

Для каждой строки `VALUES` создаются собственные mappings.

### `INSERT ... SELECT`

```sql
INSERT INTO app.user_archive (
    id,
    name,
    archived_at
)
SELECT
    u.id,
    upper(u.name),
    current_timestamp
FROM app.users u;
```

Колонки из списка `INSERT` сопоставляются с выражениями верхнего уровня в `SELECT`.

Для корректного результата рекомендуется использовать явный список выражений. `SELECT *` не может быть развёрнут без полноценного анализа метаданных источника.

### `UPDATE ... SET`

```sql
UPDATE app.users
SET name = trim(' Nikita '),
    payload = jsonb_build_object('source', 'manual'),
    updated_at = current_timestamp
WHERE id = 1;
```

### Tuple-обновление

```sql
UPDATE app.users
SET (name, payload, updated_at) = (
    trim(' Nikita '),
    jsonb_build_object('source', 'manual'),
    current_timestamp
)
WHERE id = 1;
```

### PostgreSQL `ON CONFLICT DO UPDATE`

```sql
INSERT INTO app.users (id, name, updated_at)
VALUES (1, 'Nikita', current_timestamp)
ON CONFLICT (id) DO UPDATE SET
    name = excluded.name,
    updated_at = current_timestamp;
```

Расширение показывает mappings как для основной части `VALUES`, так и для `DO UPDATE SET`.

### `MERGE`

```sql
MERGE INTO app.users target
USING app.users_stage source
ON target.id = source.id
WHEN MATCHED THEN UPDATE SET
    name = source.name,
    updated_at = current_timestamp
WHEN NOT MATCHED THEN INSERT (
    id,
    name,
    updated_at
) VALUES (
    source.id,
    source.name,
    current_timestamp
);
```

Поддерживаются ветки:

- `WHEN MATCHED THEN UPDATE SET`;
- `WHEN NOT MATCHED THEN INSERT (...) VALUES (...)`.

### Предупреждения о структуре

При включённой настройке предупреждений расширение сообщает о типичных проблемах:

- количество колонок не совпадает с количеством значений;
- одна колонка указана несколько раз;
- для значения отсутствует целевая колонка.

## Установка

В релизе предусмотрены два способа установки:

1. **Dropins** — самый простой способ для локальной установки.
2. **Local update site** — установка через стандартный мастер DBeaver.

Используйте только один способ. Не оставляйте одновременно две копии одного bundle в разных каталогах.

---

## Способ A — установка через `dropins`

Используйте архив:

```text
dbeaver-sql-column-lens-v3.5.0-dropins.zip
```

### 1. Полностью закройте DBeaver

Проверьте, что в диспетчере задач или списке процессов не осталось запущенного `dbeaver`.

### 2. Найдите корневой каталог DBeaver

Нужен каталог Eclipse-приложения, рядом с которым обычно находятся папки:

```text
configuration/
features/
plugins/
```

В Windows рядом также находится `dbeaver.exe`.

В Linux рядом находится исполняемый файл `dbeaver`.

В macOS этот каталог находится внутри пакета `DBeaver.app`; обычно удобнее использовать установку через local update site, чтобы не изменять пакет приложения вручную.

### 3. Удалите старую dropins-версию

Проверьте папку:

```text
<DBeaver>/dropins/
```

Удалите предыдущие файлы вида:

```text
com.nikbobrovsky.dbeaver.sqlcolumnlens_*.jar
```

### 4. Распакуйте архив

Распакуйте содержимое архива прямо в корневой каталог DBeaver.

После распаковки структура должна выглядеть так:

```text
<DBeaver>/
├── configuration/
├── features/
├── plugins/
└── dropins/
    └── com.nikbobrovsky.dbeaver.sqlcolumnlens_3.5.0.202607231333.jar
```

Неправильный вариант:

```text
<DBeaver>/dbeaver-sql-column-lens-v3.5.0-dropins/dropins/...
```

Правильный вариант:

```text
<DBeaver>/dropins/com.nikbobrovsky.dbeaver.sqlcolumnlens_3.5.0.202607231333.jar
```

### 5. Один раз запустите DBeaver с `-clean`

Параметр `-clean` заставляет Eclipse перечитать список plug-ins.

#### Windows

Откройте терминал в каталоге DBeaver:

```powershell
.\dbeaver.exe -clean
```

Либо временно добавьте `-clean` в поле `Объект` ярлыка, запустите DBeaver один раз, затем удалите параметр из ярлыка.

#### Linux

```bash
./dbeaver -clean
```

#### macOS

При ручной dropins-установке можно передать аргумент приложению:

```bash
open -a DBeaver --args -clean
```

После первого успешного запуска используйте DBeaver как обычно, без `-clean`.

## Способ B — локальный update site

Используйте архив:

```text
dbeaver-sql-column-lens-v3.5.0-update-site.zip
```

### 1. Распакуйте архив в постоянную папку

После распаковки должны присутствовать:

```text
site.xml
features/
plugins/
```

Не выбирайте внутреннюю папку `plugins`. В мастере нужно указать корень, где лежит `site.xml`.

### 2. Откройте мастер установки

В DBeaver выберите:

```text
Help → Install New Software…
```

### 3. Добавьте локальный репозиторий

1. Нажмите `Add…`.
2. Укажите понятное имя, например `SQL Column Lens 3.5.0`.
3. Нажмите `Local…`.
4. Выберите распакованный каталог update site.
5. Подтвердите добавление.

### 4. Установите feature

1. Отметьте **DBeaver SQL Column Lens**.
2. Нажмите `Next`.
3. Просмотрите состав установки.
4. Примите лицензию Apache License 2.0.
5. Завершите установку.
6. Согласитесь на перезапуск DBeaver.

Если DBeaver показывает предупреждение о неподписанном содержимом, убедитесь, что используется архив из доверенного источника, после чего подтвердите установку.

## Обновление с предыдущей версии

### Если старая версия была установлена через `dropins`

1. Закройте DBeaver.
2. Удалите старый JAR из `<DBeaver>/dropins`.
3. Убедитесь, что в `dropins` остался только JAR версии 3.5.0.
4. Запустите DBeaver один раз с `-clean`.

### Если старая версия была установлена через `Install New Software`

1. Откройте `Help → About DBeaver`.
2. Нажмите `Installation Details`.
3. На вкладке `Installed Software` найдите **DBeaver SQL Column Lens**.
4. Нажмите `Uninstall`.
5. Перезапустите DBeaver.
6. Установите 3.5.0 через local update site.

### Если меняется способ установки

Перед переходом с update site на dropins или наоборот полностью удалите старую копию.

Нельзя одновременно хранить:

```text
<DBeaver>/dropins/com.nikbobrovsky.dbeaver.sqlcolumnlens_старой_версии.jar
```

и установленную p2-копию того же plug-in.

Дублирование bundle может привести к тому, что DBeaver загрузит не ту версию или не активирует расширение.

## Проверка установки

### Через Installation Details

1. Откройте `Help → About DBeaver`.
2. Нажмите `Installation Details`.
3. Перейдите на вкладку `Plug-ins`.
4. В поиске введите:

```text
sqlcolumnlens
```

Ожидаемый bundle:

```text
com.nikbobrovsky.dbeaver.sqlcolumnlens
```

Ожидаемая версия:

```text
3.5.0.202607231333
```

Допустимо, если qualifier другой, но версия должна начинаться с `3.5.0`.

### Через SQL Editor

1. Откройте любое подключение или SQL Script.
2. Перейдите в SQL Editor.
3. В основной панели должна появиться кнопка **Column Lens**.
4. Вставьте тестовый запрос:

```sql
INSERT INTO test_table (id, name, status)
VALUES (1, 'Test', 1);
```

5. Поставьте курсор внутрь `1`, `'Test'` или последнего `1`.
6. Под значением должна появиться подпись соответствующей колонки.

Кнопка показывается только при активном SQL Editor. На страницах данных, ER-диаграммах и в обычных текстовых редакторах её отсутствие является нормальным поведением.

## Быстрый старт

1. Откройте SQL-файл.
2. Найдите кнопку **Column Lens** в панели редактора.
3. Убедитесь, что расширение включено.
4. Оставьте режим **Умный**.
5. Поставьте курсор внутрь нужного `INSERT`, `UPDATE` или `MERGE`.
6. Для просмотра части большого запроса выделите нужный фрагмент.
7. Для одной подписи выберите **Только значение под курсором**.
8. Для всех запросов в небольшом файле выберите **Весь редактор**.

Рекомендуемый повседневный режим — **Умный**.

## Кнопка Column Lens

Кнопка является split-button и состоит из двух частей.

### Основная часть

Обычное нажатие:

- включает расширение в активной SQL-вкладке;
- повторное нажатие выключает его;
- выбранный режим при выключении не теряется;
- другие открытые вкладки не изменяются.

### Стрелка

Стрелка открывает меню:

```text
Умный режим
Только значение под курсором
Текущий SQL-запрос
Весь редактор

Фон подписей
Парная подсветка
Вид подписей → Компактный / Расширенный

Показать все в этой вкладке
Обновить подсказки
Сбросить слой отображения
Настройки…
```

Галочка или radio-маркер показывает активный режим и включённые параметры.

### Динамическая иконка

Иконка кнопки меняется в зависимости от состояния:

- расширение выключено;
- Умный режим;
- Активное значение;
- Текущий запрос;
- Весь редактор.

## Режимы отображения

| Режим | Что отображается | Рекомендуемая нагрузка |
|---|---|---:|
| **Умный** | При выделении — значения выделенного фрагмента; без выделения — текущий запрос | Низкая |
| **Активное значение** | Одна подпись для значения под курсором | Минимальная |
| **Текущий запрос** | Все mappings текущего `INSERT`, `UPDATE`, `ON CONFLICT` или `MERGE` | Низкая |
| **Весь редактор** | Mappings всех поддерживаемых запросов в документе | Повышенная |

### Умный режим

Это режим по умолчанию.

#### Без выделения

Расширение определяет SQL statement, в котором находится курсор, и показывает только его mappings.

Пример: если в файле 11 больших `INSERT`, но курсор находится в одном запросе с 19 значениями, будут показаны только 19 подписей.

#### С выделением

Если выделенный фрагмент содержит распознанные значения, остаются только mappings, попавшие в выделение.

Это удобно для просмотра одной строки `VALUES`, части длинного выражения или небольшого участка большого SQL.

Если в выделении нет распознанных mappings, режим возвращается к поведению текущего запроса.

### Активное значение

Показывается только mapping значения, внутри которого находится курсор.

Используйте этот режим:

- в очень длинных однострочных запросах;
- при слабом компьютере;
- при работе с большим количеством строк `VALUES`;
- когда нужна максимальная визуальная чистота.

Если курсор находится между значениями, внутри имени таблицы или в `WHERE`, количество подсказок может быть равно нулю.

### Текущий запрос

Показываются все mappings только текущего statement.

Положение курсора определяет активный запрос. При переходе курсора в соседний `INSERT` набор подписей автоматически меняется.

### Весь редактор

Показываются mappings всех поддерживаемых DML-запросов документа.

Режим удобен для небольших и средних SQL-файлов, когда нужно одновременно видеть mappings нескольких запросов.

Для защиты DBeaver этот режим ограничен безопасным порогом.

## Состояние отдельных вкладок

Каждая открытая SQL-вкладка хранит собственное временное состояние:

- включено или выключено расширение;
- текущий режим;
- временный обход безопасного лимита.

Пример:

- во вкладке `small_insert.sql` можно выбрать **Весь редактор**;
- во вкладке `large_load.sql` можно оставить **Текущий запрос**;
- переключение режима в одной вкладке не изменит уже открытые соседние вкладки.

### Что запоминается глобально

Последний режим, выбранный через меню, сохраняется как режим по умолчанию для **новых** вкладок.

Например:

1. Во вкладке A выбран режим **Текущий запрос**.
2. Уже открытая вкладка B сохранит свой прежний режим.
3. Новая вкладка C откроется в режиме **Текущий запрос**.

### Что не запоминается после закрытия вкладки

- временное включение или выключение конкретной вкладки;
- принудительный режим **Показать все в этой вкладке**;
- временная комбинация состояния вкладки.

Глобальное поведение новых вкладок настраивается в Preferences.

## Защита от зависаний

Большое количество inline-аннотаций увеличивает нагрузку на layout SQL Editor, особенно при длинных строках и включённом soft wrap.

По умолчанию безопасный порог равен:

```text
300 mappings
```

Правило работает так:

- от 0 до 300 mappings — режим **Весь редактор** отображает всё;
- начиная с 301 mapping — автоматически включается отображение только текущего запроса;
- исходный выбранный режим остаётся **Весь редактор**, но фактический render-plan становится безопасным;
- status line показывает общее найденное количество.

Пример сообщения:

```text
SQL Column Lens · Безопасный · текущий запрос · 19 подсказок · найдено 846 · «Показать все в этой вкладке»
```

### Показать всё один раз

Откройте меню кнопки и выберите:

```text
Показать все в этой вкладке
```

После этого:

- расширение включится;
- режим станет **Весь редактор**;
- безопасный лимит временно не применяется;
- override действует только для этой вкладки;
- при смене режима, выключении расширения или закрытии вкладки временный override сбрасывается.

Используйте эту команду осознанно: сотни inline-подсказок могут увеличить время layout и прокрутки.

### Изменение порога

Порог меняется в:

```text
Preferences → SQL Column Lens
```

Допустимый диапазон:

```text
20–5000
```

Рекомендуется оставлять значение `300`, если нет измеренной причины его повышать.

## Внешний вид подписей

### Компактный

Формат:

```text
column_name:
```

Пример:

```text
id: 10, name: 'ООО Ромашка', inn: '4253000000'
```

Преимущества:

- занимает меньше места;
- уменьшает ширину строки;
- реже вызывает переносы;
- создаёт меньшую нагрузку на layout.

Компактный вид используется по умолчанию.

### Расширенный

Формат:

```text
column_name [type] #position:
```

Пример:

```text
id [int] #1: 10
name [varchar(255)] #2: 'ООО Ромашка'
```

Тип показывается, только если:

- включена настройка загрузки типов;
- SQL Editor связан с активным подключением;
- таблица успешно найдена в метаданных DBeaver;
- колонка существует в найденной таблице.

Если тип получить не удалось, подпись останется рабочей, но часть `[type]` будет отсутствовать.

### Сокращение длинных имён

Длинные идентификаторы сокращаются через `…`, при этом сохраняется начало и окончание имени.

Пример:

```text
status_closed_name
```

может отображаться как:

```text
status_closed_nam…name:
```

Сокращение влияет только на визуальную подпись. SQL-текст и mapping не изменяются.

Полное имя доступно в hover активного значения.

### Фон подписей

Пункт **Фон подписей** добавляет отдельный фон inline-label.

Отключите фон, если:

- используется контрастная тема;
- фон конфликтует с цветами SQL Editor;
- хочется сделать подписи менее заметными;
- требуется немного снизить визуальную нагрузку.

## Парная подсветка и hover

### Парная подсветка

Когда курсор находится внутри распознанного значения, расширение подсвечивает:

1. само значение;
2. соответствующую колонку в целевом списке или в левой части `SET`.

Это позволяет быстро увидеть связь:

```text
target column ↔ source value
```

При обычном текстовом выделении дополнительная парная подсветка временно не рисуется. Это сделано специально, чтобы не смешивать цвета SQL Column Lens с синей подсветкой выделения и подсветкой совпадений DBeaver.

### Hover активного значения

Наведите курсор мыши на подсвеченное значение. Hover может содержать:

```text
Column: status_closed_name
Type: varchar(255)
Position: 16 of 19
Table: dm_esfl_esul.fct_esul
Value: NULL
Kind: INSERT VALUES
```

Дополнительно могут отображаться предупреждения о структуре запроса.

### Что означает каждое поле

| Поле | Значение |
|---|---|
| `Column` | Полное имя целевой колонки |
| `Type` | Тип из метаданных активного подключения, если доступен |
| `Position` | Позиция значения в текущем positional mapping |
| `Table` | Целевая таблица |
| `Value` | Текст выражения, сокращённый до безопасной длины |
| `Kind` | Вид mapping: `INSERT VALUES`, `INSERT SELECT`, `UPDATE SET`, `MERGE` и т. п. |

В версии 3.5.0 hover является информационным. Интерактивные кнопки копирования и навигации внутрь hover в этот релиз не включены.

## Status line

При включённой настройке в нижней строке состояния SQL Editor отображаются:

- текущий режим;
- фактическое количество подсказок;
- активная таблица или колонка;
- позиция активного значения;
- предупреждение безопасного режима;
- результат команд обновления и сброса.

Примеры:

```text
SQL Column Lens · Умный · текущий запрос · 19 подсказок · dm.clients
```

```text
SQL Column Lens · Активное значение · 1 подсказок · status [varchar(50)] · 4/19
```

```text
SQL Column Lens · Весь редактор · 209 подсказок · 11 запросов
```

```text
SQL Column Lens · выключен
```

Сообщения о переключении, обновлении и сбросе слоя отображаются временно. Текущее состояние режима остаётся видимым постоянно, пока настройка status line включена.

## Обновление и восстановление отображения

### Обновить подсказки

Команда:

```text
Обновить подсказки
```

Она:

- инвалидирует кэш анализа текущего документа;
- повторно анализирует SQL;
- создаёт актуальный набор mappings;
- не требует закрытия вкладки или перезапуска DBeaver.

Используйте её, когда:

- SQL был массово заменён или отформатирован;
- после большого редактирования отображается устаревший набор;
- режим изменён, но визуальная часть не обновилась;
- требуется принудительно пересчитать запрос.

### Сбросить слой отображения

Команда:

```text
Сбросить слой отображения
```

Она:

- удаляет текущие inline-аннотации;
- снимает парную подсветку;
- освобождает painter/inline-support текущей вкладки;
- создаёт слой заново;
- сохраняет текст, позицию курсора и прокрутку;
- не перезапускает DBeaver.

Используйте её, если появились:

- пустые зазоры в строке;
- зависшая старая подпись;
- неверная геометрия после soft wrap;
- подпись в неправильной позиции;
- визуальный конфликт после работы стороннего painter или темы.

Обычно сначала достаточно **Обновить подсказки**. **Сбросить слой отображения** — более глубокое восстановление.

или через Preferences:

### Настройки по умолчанию

| Настройка | Значение по умолчанию | Назначение |
|---|---:|---|

| Парная подсветка | Включено | Подсветка активного значения и колонки |

| Показывать предупреждения | Включено | Несовпадения и дубликаты |

| Безопасный порог | 300 | Максимум mappings для автоматического editor-wide render |

### Какие параметры относятся к новым вкладкам

Следующие параметры задают начальное состояние новых вкладок:

- **Включать SQL Column Lens в новых вкладках**;
- **Режим по умолчанию**.

Уже открытые вкладки сохраняют собственные временные `enabled` и `mode`.

### Какие параметры глобальные

Параметры внешнего вида и поведения применяются глобально:

- стиль подписей;
- inline-подписи;
- фон;
- status line;
- подсветка;
- типы;
- позиция;
- предупреждения;
- задержка;
- безопасный лимит.

### Задержка обновления

Допустимый диапазон:

```text
0–2000 мс
```

Рекомендации:

- `0–100` мс — максимально быстро, но больше пересчётов при наборе;
- `250` мс — рекомендуемое значение;
- `400–800` мс — для очень больших SQL-файлов;
- более `1000` мс — только если задержка не мешает работе.

Изменение положения курсора при уже готовом анализе обрабатывается без полной задержки редактирования.

### Типы колонок

Типы загружаются в фоне из метаданных активного DBeaver datasource.

Важно:

- positional mapping работает и без подключения;
- типы являются дополнительной информацией;
- при ошибке метаданных подписи не пропадают;
- результат кэшируется, чтобы не запрашивать таблицу при каждом движении курсора;
- полностью квалифицированное имя `schema.table` повышает вероятность точного поиска.

## Рекомендуемые сценарии использования

### Обычная ежедневная работа

Используйте:

```text
Умный + Компактный
```

Это лучший баланс между информативностью и производительностью.

### Один большой `INSERT`

Используйте:

```text
Текущий запрос + Компактный
```

Все значения текущего запроса будут подписаны, а остальные statements не повлияют на layout.

### Очень длинный однострочный `INSERT`

Используйте:

```text
Активное значение + Парная подсветка
```

Курсор показывает одну связь между значением и колонкой без перегрузки строки.

### Файл с 11 `INSERT`

Для постоянной работы оставьте **Умный**.

Для разовой проверки всех mappings:

1. Выберите **Весь редактор**.
2. Если сработал безопасный режим, нажмите **Показать все в этой вкладке**.
3. После проверки вернитесь в **Умный** или **Текущий запрос**.

### Многострочный `VALUES`

В версии 3.5.0 отдельные режимы «только активная строка» и «первая плюс активная» ещё не реализованы.

Практичные варианты:

- **Умный** и выделение одной строки;
- **Активное значение** для одной подписи;
- **Текущий запрос** для всех строк statement.

### Поиск ошибки в позиции

1. Включите **Расширенный** вид.
2. Поставьте курсор в подозрительное значение.
3. Смотрите `#position` в подписи.
4. Проверьте `Position N of M` в hover.
5. Используйте парную подсветку для проверки целевой колонки.

## Ограничения

### Требуется явный список целевых колонок

Конструкция без списка колонок не даёт надёжного positional mapping:

```sql
INSERT INTO app.users
VALUES (1, 'Nikita');
```

Рекомендуемый вариант:

```sql
INSERT INTO app.users (id, name)
VALUES (1, 'Nikita');
```

### `SELECT *` не разворачивается

```sql
INSERT INTO target (id, name)
SELECT * FROM source;
```

Расширение не выполняет запрос к источнику для разворачивания `*`. Используйте явные expressions.

### Это tolerant-parser, а не валидатор SQL

Расширение старается работать с частично написанным SQL, но экзотические диалектные конструкции могут не распознаться.

### Типы доступны не всегда

Отсутствие типа не означает отсутствие mapping. Это может означать:

- нет активного подключения;
- таблица не найдена;
- не выбран правильный datasource;
- недостаточно прав на metadata;
- используется временная или динамическая таблица;
- диалект DBeaver не отдал объект через стандартную metadata-модель.

### Нет интерактивных действий внутри hover

В 3.5.0 не включены:

- копирование колонки кнопкой из hover;
- переход к колонке из hover;
- временное скрытие отдельной подписи;
- следующее и предыдущее значение;
- история перехода «колонка ↔ значение».

### Нет отдельной стратегии для строк `VALUES`

Режимы «все строки», «только активная строка» и «первая плюс активная» не вынесены в отдельную настройку этого релиза.

## Устранение неполадок

### Кнопка Column Lens не появилась

Проверьте по порядку:

1. Активна именно вкладка SQL Editor.
2. Bundle виден в `Installation Details → Plug-ins`.
3. Версия начинается с `3.5.0`.
4. DBeaver запущен на Java 21.
5. Нет второй старой копии plug-in.
6. После dropins-установки DBeaver был один раз запущен с `-clean`.
7. Архив распакован без лишнего промежуточного каталога.

### Plug-in виден, но не активируется

Наиболее вероятные причины:

- DBeaver работает на Java ниже 21;
- не хватает требуемого Eclipse API inline annotations;
- одновременно установлены две версии bundle;
- повреждён JAR;
- используется несовместимая нестандартная сборка DBeaver.

Проверьте `Error Log`:

```text
Window → Show View → Error Log
```

Ищите записи с:

```text
com.nikbobrovsky.dbeaver.sqlcolumnlens
```

### Подписи не появляются

1. Убедитесь, что кнопка включена.
2. Проверьте, что включено **Показывать inline-подписи**.
3. Поставьте курсор внутрь поддерживаемого statement.
4. Используйте явный список целевых колонок.
5. Выберите режим **Текущий запрос**.
6. Нажмите **Обновить подсказки**.
7. При необходимости выполните **Сбросить слой отображения**.

### В режиме «Активное значение» показано 0 подсказок

Курсор должен находиться непосредственно внутри распознанного выражения.

Например, для:

```sql
VALUES (10, 'ООО', NULL)
```

поставьте курсор внутрь `10`, `'ООО'` или `NULL`, а не между запятыми.

### Весь редактор показывает только один запрос

Скорее всего, сработал безопасный режим.

Посмотрите status line. Если найдено больше установленного порога, используйте:

```text
Column Lens → Показать все в этой вкладке
```

Либо увеличьте порог в Preferences, понимая влияние на производительность.

### DBeaver начал подвисать

1. Переключитесь в **Активное значение** или **Текущий запрос**.
2. Верните безопасный порог к `300`.
3. Используйте компактный вид.
4. Отключите фон подписей.
5. Увеличьте задержку обновления до `400–800` мс.
6. Не используйте постоянный forced show-all для огромного файла.
7. Отключите soft wrap для очень длинных однострочных запросов, если он создаёт дополнительную нагрузку.
8. Выполните **Сбросить слой отображения**.

### Остались пустые промежутки или старая геометрия

Выполните:

```text
Column Lens → Сбросить слой отображения
```

Команда пересоздаёт inline-support текущей вкладки без перезапуска DBeaver.

### Цвета плохо сочетаются с темой

Попробуйте:

- отключить **Фон подписей**;
- отключить **Парную подсветку**;
- настроить annotation colors в стандартных настройках DBeaver/Eclipse;
- использовать компактный вид.

### Не показываются типы

Проверьте:

1. Включена настройка **Загружать типы колонок при активном подключении**.
2. SQL Editor привязан к нужному datasource.
3. Таблица существует и доступна в навигаторе DBeaver.
4. В SQL указано квалифицированное имя, например `schema.table`.
5. Колонка существует в metadata.

Сопоставление колонок и значений продолжает работать без типов.

### Горячая клавиша не работает

Откройте:

```text
Preferences → General → Keys
```

Найдите команду **Включить / выключить SQL Column Lens**, проверьте конфликт и назначьте другое сочетание.

Используйте:

```text
File → Export → Plug-in Development → Deployable features
```

При экспорте включите:

- упаковку plug-ins в JAR;
- metadata repository;
- class files from workspace.

После сборки проверьте, что OSGi manifest не заменён стандартным коротким manifest от утилиты `jar`.

В итоговом JAR должны присутствовать:

```text
META-INF/MANIFEST.MF
plugin.xml
about.html
icons/
com/nikbobrovsky/dbeaver/sqlcolumnlens/**/*.class
```

## Производительность и архитектура

Версия 3.5.0 сохраняет оптимизации предыдущего релиза:

- SQL анализируется вне UI-потока;
- документ лексируется один раз для editor-wide анализа;
- результат анализа кэшируется по ревизии документа;
- одна editor-session создаётся на вкладку;
- inline-аннотации переиспользуются, если их позиция и текст не изменились;
- набор аннотаций применяется атомарно;
- redraw временно приостанавливается во время обновления;
- позиция курсора, прокрутка и горизонтальный offset восстанавливаются;
- типы колонок загружаются в фоне и кэшируются;
- безопасный режим предотвращает неограниченный editor-wide render.
